# Beer Portfolio Acceptance Criteria

## 全局验收原则

- 所有任务必须有任务单、执行报告和验收报告。
- 任务完成必须经过 Reviewer 独立验收。
- 不允许虚构测试结果、命令输出、截图或功能状态。
- 对业务功能的修改必须对应唯一任务编号。

## P0 功能验收

- [ ] 左侧固定个人信息区在桌面端正常 sticky。
- [ ] 右侧内容使用自然页面滚动。
- [ ] 锚点导航可点击、可键盘操作，并能高亮当前区域。
- [ ] About 模块能说明当前身份、工作方式和关注领域。
- [ ] Experience 模块能展示时间、角色、说明、成果和技术标签。
- [ ] Featured Projects 展示 4 个核心项目。
- [ ] Other Projects 能展示中小项目，移动端单列。
- [ ] Contact 模块包含邮件、简历和 GitHub 入口。
- [ ] 移动端小于 768px 时为单栏布局。
- [ ] 4 个核心项目详情页可访问。
- [ ] 404 页面存在。
- [ ] 首页和项目页有基础 SEO 元信息。

## 技术验收

- [ ] TypeScript 构建通过。
- [ ] Lint 或项目等效静态检查通过。
- [ ] 自动测试通过，或任务明确说明未配置测试框架。
- [ ] 生产构建无控制台报错。
- [ ] 不提交 token、API Key 或账号凭据。

## 设计验收

- [ ] 深色背景不压抑，文字层级清晰。
- [ ] 青绿色只作为强调色使用。
- [ ] 项目图片比例统一，建议 16:10。
- [ ] 不使用过度 3D、粒子、玻璃卡片或大型渐变。
- [ ] hover 和进入动效克制，不影响阅读。

## 响应式验收

- [ ] 桌面端大于等于 1024px 使用左右分栏。
- [ ] 平板端 768px 至 1023px 布局稳定。
- [ ] 手机端小于 768px 单列展示。
- [ ] 内容不溢出，不互相遮挡。

## 无障碍验收

- [ ] 图片有 alt。
- [ ] 图标链接有 aria-label。
- [ ] 交互元素有清晰 focus。
- [ ] 支持 `prefers-reduced-motion`。
- [ ] 外部链接在新窗口打开时有安全属性。

## 性能验收

- [ ] 首屏避免加载大量项目大图。
- [ ] 项目图片懒加载。
- [ ] 使用 WebP 或 AVIF 优先。
- [ ] 不加载复杂 3D 资源。
- [ ] Lighthouse Performance、Accessibility、Best Practices、SEO 目标均为 90+。
